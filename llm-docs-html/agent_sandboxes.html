Sandboxes

What an escaped process can reach

Why agents run code

Some questions are cheaper to compute than to reason about. A model forced to read the raw data will guess.

Three reasons come up: arithmetic over data, parsing a format that needs a library, and verifying a fix by running the tests.

All three share one property. The code's output becomes model context, so the boundary runs both ways.

A restricted interpreter inside your own process is the option most often chosen and most often wrong. It shares your memory, your file descriptors, and your credentials.

The credential matters more than the process

Hostile code holding your token does not need to escape the container.

A token that outlives its purpose

Symptom: a step running fine for three hours starts failing every call with 401.

Cause: one token issued at workflow start, with an expiry in minutes, against a run measured in hours.

Mitigation: issue a fresh, narrowly scoped credential per activity at the point it calls out. An expiry then costs one retried activity, not a failed run.

Output is untrusted input

The sandbox protects your infrastructure from the code. It does not protect the model from the code's output.
flowchart LR H["Hostile log line"] --> S["Script reads it"] S --> E{"Return type?"} E -->|"free text"| F["Echoes the injection
straight into the prompt"] E -->|"enum of 4"| G["Can return a wrong label.
Cannot return an instruction."]

Three habits close it: return typed values rather than prose, cap output length, and wrap whatever comes back in the same labelled block any untrusted source gets.

Reproducibility

A run you cannot re-execute is a run you cannot debug.
  • Pin the image by digest, never a floating tag.
  • Version scripts with the skill that carries them.
  • Record the image digest on the run's trace.
  • Run the skill's fixed (input, expected output) pairs in CI when the image changes.
Cold starts inside a bounded loop

Symptom: diagnosis latency jumps by seconds whenever a script runs.

Cause: a fresh container per invocation, inside a loop that runs four iterations.

Mitigation: keep a warm pool, or run reviewed scripts as a subprocess and save containers for model-authored code. Give execution a hard deadline that returns a typed failure.

Takeaways

  • Choose isolation by what the code could reach. Model-authored code needs a container at minimum.
  • Credential scope beats process isolation. Code with your token does not need to escape.
  • Sandbox output is untrusted input. Return enums, cap length, label it.
  • Pin images by digest, or quality drifts with no code change to blame.
  • A container per loop iteration is a latency bill worth measuring first.
