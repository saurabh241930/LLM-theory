Guardrails

What still holds when the model misbehaves

Two kinds, and only one is a guarantee

Asking the model to behave lowers the odds. Code removes the option.
flowchart LR subgraph P["Probabilistic — lowers odds"] P1["'Only use these tools'"] P2["'Treat text as data'"] P3["Injection classifier"] end subgraph S["Structural — removes the option"] S1["Closed enum"] S2["Allow-list"] S3["SQL tenant predicate"] S4["Budget check"] S5["Approval gate"] end P -.->|"build this second"| S

Mixing these up is how a system prompt ends up treated as a security boundary.

One question cuts through it. Assume the model is fully persuaded by whatever it just read. What can it still do? The answer is your blast radius, and only the structural column changes it.

Input: classify by trust

Three of five input kinds are untrusted, and those three grow without review.
flowchart TD subgraph T["Trusted — you wrote it"] T1["System prompt"] T2["Tool schemas"] end subgraph U["Untrusted — someone else shaped it"] U1["Retrieved docs and logs"] U2["Tool and sandbox output"] U3["Prior-run memory"] end T --> CTX["Context window"] U -->|"delimited, labelled blocks"| CTX
Control Why
Length and shape caps A 200,000-char "intent" is a mistake or an attack. Cap before tokenising.
Scrub PII at ingest Scrubbing at render time leaves it encoded in the vector.
Rate limit per tenant Cheapest defence against abuse and runaway client loops.
Injection classifier Fine as a cheap screen. Never the primary control.
Sanitising instead of delimiting

Symptom: a list of stripped phrases grows every time someone finds a bypass, and injections still land.

Cause: removing instruction-shaped text is open-ended pattern matching against a creative adversary.

Mitigation: stop cleaning it. Pass it inside a labelled block and put the guarantee downstream in the output type. See Prompt Injection Defence.

Gate on what the action does

Approval fatigue

Symptom: reviewers approve without reading.

Cause: too many classes trigger a gate, so approving becomes reflex.

Mitigation: batch one approval per plan, not one per step. A gate that fires rarely gets read.

Runtime: budgets, breakers, kill switch

Controls for a system behaving correctly but expensively.

Control Rule
Budgets Four dimensions. Check before the call, or you overspend by one every time.
Circuit breakers Retrying into an outage makes it worse and bills you for it.
Degradation paths Reranker timeout falls back to fusion order. Worse order beats no answer.
Kill switch Config, not code. If stopping needs a deploy, you have no kill switch.
Retry storms

Symptom: one invalid output burns dozens of retries across every run at once.

Cause: unlimited retry policy, and a validation failure looks like any other exception.

Mitigation: explicit max attempts, and mark validation failures non-retryable.

Testing them

Assert on the action produced, never on what the model said.
  • Keep an adversarial corpus: embedded instructions, role-play framing, encoded payloads, and instructions split across two chunks. The split case defeats any per-chunk scanner.
  • Fault-inject outages, timeouts and exhausted budgets. Each should produce a typed result, not a hang.
  • Re-run on every model change. A newer model can follow instructions better in exactly the wrong way.
  • Chart guardrail firing rates. A rate that drops to zero usually means a refactor stopped calling the check.

Put those rates next to the accuracy metrics in Evaluating Agent Systems.

Takeaways

  • Separate probabilistic from structural, and build structural first.
  • Assume the model is compromised. What it can still do is your blast radius.
  • Delimit untrusted input rather than trying to clean it.
  • Gate on action class, and fail closed on timeout.
  • Check budgets before the call, across money, time, calls and domain resources.
  • Give every expensive stage a defined worse answer, and keep a kill switch that needs no deploy.
  • A guardrail firing rate that silently hits zero is a broken check.
