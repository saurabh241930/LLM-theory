Agentic RAG

When choosing the source is itself the judgement

The RAG family, and what each rung adds

Plain RAG retrieves once. Corrective RAG grades what came back. Agentic RAG lets the model choose the source, the query, and when to stop.
Approach What it adds LLM calls per query Best for
Plain RAG Retrieval before generation 1 The answer sits in one passage
Corrective RAG (CRAG) A grader between retrieve and generate; refine or rewrite on weak evidence ~3 batched Refusing to answer from junk
Agentic RAG Model picks the tool, the query, and when to stop iterations x (choice + grade) + 1 proposal; ceiling 9 Heterogeneous, unreliable sources
Graph RAG Entity graph traversed by relationship instead of similarity 1 SQL walk, 0 LLM calls when scoped Relationships over a small durable set
Each rung costs more. Buy a rung only when the one below actually fails.

Agentic RAG earns its cost over sources that are not interchangeable. It is the wrong choice when one corpus holds the answer, because then you are paying a model to choose between one option.

The test: is choosing the source part of the diagnosis?

If a fixed pipeline order would be right most of the time, use a fixed pipeline. If the right source depends on what went wrong, the choice is the judgement.

The running example makes the test concrete. The Diagnoser has four retrieval tools, and each answers a different question:

Tool Answers Right when
search_logs What happened? A serialization bug; the evidence is in this run's own log
search_docs What does this mean? A licence failure needs the authoritative error-code semantics
load_skill What do we do? A solver divergence needs the operational playbook
recall_similar_failures What worked last time? A signature seen before with a known-good remediation
Four sources, no fixed order that is right more than about half the time.

A licence checkout failure needs the docs and the log, and skills add nothing. A solver divergence needs the log and the skill, and the docs are noise. A serialization bug is answered by past runs alone. Any fixed order guesses wrong roughly half the time, and that is what makes the choice worth an LLM call.

The loop contract

Four iterations, one tool-choice call and one batched grade call each, one final proposal. Nine LLM calls, enforced in Python.
sequenceDiagram participant W as Workflow participant D as diagnose activity participant T as Retrieval tools participant G as Grader (Haiku 4.5) participant P as Proposer (Sonnet 5) W->>D: Failure record loop up to 4 iterations D->>D: choose tool + query D->>T: call it T-->>D: Evidence list D->>G: grade batch (one call) G-->>D: GradedEvidence list end D->>P: propose(kept evidence) P-->>D: RemediationAction D-->>W: RemediationAction

Three conditions stop the loop, whichever fires first: at least three items graded correct, two consecutive iterations returning nothing outside the already-seen set, or the iteration cap. Every exit produces a typed action, including the one where nothing was found.

The grading step is the corrective part, and it runs inside every iteration rather than once at the end. Each candidate is graded correct, ambiguous, or incorrect.

Why three verdicts instead of relevant/irrelevant

A binary verdict hinges entirely on the grader being right at one threshold, and graders are not perfectly calibrated. Three grades let the upper threshold clear an answer, the lower one discard it, and the middle absorb the disagreement.

ambiguous is the honest label for most real diagnoses. A 2023R1 page that is topically near-identical to a 2025R2 failure is not irrelevant and is not correct; a version mismatch alone downgrades it.

What it costs

~$0.046 typical, ~$0.11 worst case, against a solver job measured in cluster-hours.
Role Model Calls Cost
Tool choice Haiku 4.5 ≤ 4 ~$0.004
Grade (batched) Haiku 4.5 ≤ 4 ~$0.068 worst case
Proposal Sonnet 5 ≤ 1 ~$0.027
Ceiling — 9 ~$0.11 worst case
The expensive model proposes once; the cheap model does the high-volume judgement.

The latency budget is 60 seconds, which is generous against a failure on a job measured in hours. The honest framing is never "how do we make diagnosis faster" but "how do we spend 60 seconds on accuracy".

Where it goes wrong

Three failure modes, all of them cheap to prevent and expensive to discover late.
Runaway iterations

Symptom: the loop rewrites its query repeatedly, never converges, and burns tokens without producing a result.

Cause: an unbounded rewrite can wander away from the original failure.

Mitigation: the cap is enforced in code, not requested in a prompt. Tracking seen evidence IDs stops a rewrite that keeps returning the same chunks. Escalation on exhaustion is a result, not a bug: sometimes the corpora genuinely do not cover the failure.

Prompt injection through retrieved text

Symptom: a diagnosis recommends downloading every project file, or some other unrelated action.

Cause: a solver log or shared runbook contains a line that reads as an instruction, and the model treats it as one.

Mitigation: state in both the grader and proposal prompts that retrieved text is data, wrap it in delimited labelled blocks, and rely on the closed remediation enum as the real backstop. Injected text cannot name an action that does not exist.

Grader drift

Symptom: the escalation rate creeps upward over weeks with no code change.

Cause: the grader model moved behind a floating alias, or a prompt edit shifted the boundary between ambiguous and incorrect.

Mitigation: pin exact model IDs. Keep a frozen labelled set and run it in CI on every prompt or model change; alert on a shift in the verdict distribution.

Takeaways

  • Use agentic RAG when choosing the source is part of the answer. With one corpus, a fixed pipeline is cheaper and more predictable.
  • Bound the loop in code: iteration cap, sufficiency threshold, and a no-new-evidence exit.
  • Grade inside every iteration rather than once at the end, so a bad retrieval never becomes a bad action.
  • Three verdicts beat two. ambiguous is the honest label for most real evidence.
  • Finding nothing is a typed escalation, not an exception and not a guess.
