The problem

An engineer types "bracket fatigue at 200 Hz" and wants a finished report. The solve takes four hours, costs cluster-time, and can fail six ways.

That gap is the design problem. It is a good teaching example because every hard part of agent engineering shows up for a concrete reason.

The run outlives the request, so you need durable execution. The solver burns cluster-hours, so you need budgets and gates. Logs are redacted, so you need retrieval. The model can invent a step name, so you need validation.

The main loop

One entry point for new work. Approval, polling and diagnosis all route back through it.

Nothing here is decided by an LLM reading prose. The workflow branches only on a validated plan, a status enum, or a typed remediation.

Failure modes worth knowing

Each is a real bug with a symptom you can recognise in a log.
The 600-second wait ceiling

Symptom: the wait tool times out while the solver is still running.

Cause: it blocks inside one HTTP request, capped at 600 s.

Mitigation: poll from a durable timer, outside the request.

Completed and out-of-date coexist

Symptom: the agent reports a finished run on stale numbers.

Cause: writing a field marks downstream fields stale without touching method status.

Mitigation: the done check reads both axes: status is complete and every output is up to date.

Hallucinated step names

Symptom: first activity fails with unknown step 'meshing'.

Cause: structured outputs constrain shape, not membership.

Mitigation: validate against the real schema first, and return the valid names as feedback.

Injection through a solver log

Symptom: a diagnosis recommends downloading every project file.

Cause: a log line reads as an instruction and the model obeys.

Mitigation: labelled blocks, plus a closed enum so injected text cannot name an action that does not exist.

Poisoned memory

Symptom: a fix that never worked, recommended confidently.

Cause: a coincidence was written back as a lesson.

Mitigation: write only on terminal success where the fix was the sole change, and decay weights on reuse failure.

Takeaways

  • Architecture is a checklist against real constraints. A four-hour solve eliminates two of three candidates on its own.
  • Keep the orchestrator deterministic. Every LLM and HTTP call is a retryable activity.
  • The model proposes; the guardrails dispose.
  • Have numbers ready: 600 s wait ceiling, 9-call budget, ~$0.046 per diagnosis, 4.0 solver-hour cap.
  • State the trade-off you accepted, not only the property you gained.
