Tool Design

The schema is all the model sees

The model cannot read your code

It sees the schema and nothing else. Whatever the schema leaves out, it guesses.
flowchart LR C["Your function
units, ranges, rules"] --> S["JSON Schema
the only thing sent"] S --> M["Model"] C -.->|"lost here"| X["❌ units
❌ valid range
❌ business rules"]
Weak Strong What it buys
value: Any value: float + unit in the description No guessing on type or unit
kind: str kind: RemediationKind The legal values, enforced at decode
content: bytes content: FileRef A 2 GB mesh never enters context
value: Any is not a contract

Symptom: the model writes "0.5" where a float is expected, and it surfaces later as a confusing solver error.

Cause: Any compiles to an empty schema {}. No type, no unit, no range.

Mitigation: build a typed field schema from your own reflection at startup. Coerce or reject in your wrapper, before the call goes out.

Errors are prompts

The model reads your error and decides what to do next. Say what would work.
flowchart TD E1["'invalid step'"] --> G1["Model guesses again"] --> G2["Guesses again"] --> G3["Loops"] E2["'unknown step meshing;
known: geometry, mesh, solve'"] --> F["Model picks 'mesh'"] --> OK["Fixed in one retry"] 
# Names the problem. Model has to guess the fix.
raise ValueError("invalid step")

# Names the problem and the way out.
raise ValueError(f"unknown step {step!r}; known: {sorted(schema.steps)}")

Cap the list so a schema with 400 fields does not produce a 400-item error. Mark validation failures non-retryable, so they trigger a corrected retry instead of repeating the same prompt.

Never show an ambiguous return

A tool that sometimes returns a value and sometimes returns nothing is where agents break quietly.
flowchart TD T["run_transaction(...)"] --> Q{"long running?"} Q -->|no| R["Returns the result"] Q -->|yes| H["Returns a handle
work still going"] R --> W["Your wrapper"] H --> W W --> TY["One typed object
the model never sees bare None"]

A bare None gives the model no way to tell "done, no output" from "started, come back later". Your wrapper converts both into one typed result.

A handle you cannot pick back up

Symptom: after a worker restart, nothing can retrieve a transaction that is still running.

Cause: the handle is a client-side object with no server identity.

Mitigation: persist (project, step, transaction) as the durable key. Rebuild state from a fresh status read on every poll.

Files go by reference

A signature taking raw bytes turns the file into tokens.
flowchart LR subgraph BAD["upload_file(content: bytes)"] B1["2 GB mesh"] --> B2["tool arguments"] --> B3["context window 💥"] end subgraph GOOD["upload_file(content: FileRef)"] G1["2 GB mesh"] --> G2["object storage"] G2 -->|"streams directly"| G3["the API"] G4["model sees
a URI string"] end

This generalises. Any argument whose size the domain does not bound should be a reference. Any result that could be large should be a reference plus a summary.

Idempotency lives in the wrapper

Retries are automatic. A tool that spends money needs a ledger check first.
flowchart TD A["Activity retried"] --> K["Compute key
run_id:ordinal:transaction"] K --> C{"Key in ledger?"} C -->|yes| L["Return recorded result
resume"] C -->|no| I["Invoke, then record"] 
def run_transaction(client, project, step, transaction, args, *, idempotency_key):
    if already_applied(idempotency_key):
        return load_handle(idempotency_key)      # resume, never resubmit
    result = invoke(client, project, step, transaction, args)
    record(idempotency_key, result)
    return result

Build the key from identifiers the caller already has. A UUID minted inside the function is different every attempt and protects nothing.

Keep the surface small

Every tool schema is paid on every call, and more tools make selection harder.

Takeaways

  • The schema is the model's whole view of your function. Enums constrain; Any does not.
  • Errors should list the valid options, and validation failures should be non-retryable.
  • Never return a bare None, and never persist a client-side handle.
  • Pass file references, not bytes.
  • Check the idempotency ledger before acting, keyed by identifiers the caller already has.
